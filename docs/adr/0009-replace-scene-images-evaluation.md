# 0009. Evaluation (#93): replace the 20 Grok-generated scene images with Mistral/FLUX output

- **Status**: Accepted — QC gate executed 2026-11-15 (illustration arm passed 20/20; see below)
- **Date**: 2026-11-15
- **Deciders**: Andreas Gerlach
- **Supersedes**: none (amends ADR 0008: when the replacement ships, the scene files leave its attribution list)
- **Related issues**: #93 (this evaluation), epic #91; icon/mark replacement is the separate follow-up

## Scope

The 20 scene JPGs in `public/scenes/*.jpg` only. Per the owner's decision on
#93, `public/og.jpg`, the favicon and the PNG icons stay in place (tracked by
the icon/mark follow-up), so this ADR changes nothing about them.

## Context

ADR 0008 keeps the Grok-generated bytes plus their "Created with Grok"
attribution while replacements are evaluated. #93 asks for research + a
prototype, with three acceptance criteria: side-by-side visual QC of ≥3
regenerated scenes against the current ones, a recorded cost/latency estimate,
and a replace/keep recommendation. The current set was audited image by image:
photorealistic warm/golden-hour Lisbon scenes (azulejo tiles, cobblestones,
terracotta roofs, vintage radios, pastelaria/padaria counters), mostly
people-free, several with legible Portuguese signage, ~1168–1200 px wide,
90–260 KB, displayed at a 16:9 `object-cover` hero crop
(`src/components/lesson-player.tsx:217`) and a 112×128 thumb
(`src/routes/practice.tsx:57`).

## Options evaluated (research, 2026-11-15)

| Option | Findings | Verdict |
| --- | --- | --- |
| **Mistral built-in `image_generation` tool** in chat completions (BFL FLUX1.1 [pro] Ultra) | `POST /v1/chat/completions` with `tools:[{type:"image_generation"}]` and a `messages` prompt (per the official cookbook "Using Connectors in Chat Completions"). The response is **multi_completion** (`choices[].messages[]`): the model emits a `generate_image` tool_call and the result arrives as a `role:"tool"` message whose **`content` is a JSON string** — `{"url": "https://…blob.core.windows.net/images/…/image.jpg?sig=…"}` (observed live 2026-11-15; parse string values, the host is not files.mistral.ai). `image_url` chunks and agents-style `tool_file`/`file_id` chunks (download via `GET /v1/files/{id}/content`) are handled too. Billed as a built-in tool at ~$100/1k images = **$0.10/image**. Mistral ToS assigns all IP in the Output to the user and requires **no attribution phrase** — only the AI-generated disclosure Bica already shows (EU AI Act Art. 50). FLUX1.1 Ultra leads published photorealism evals as of mid-2026. **Endpoint notes (verified 2026-11-15):** the legacy Agents/Conversations API (`/v1/agents`, `/v1/conversations`) is **deprecated and 404s** ("no Route matched") — do not use it; the chat-completions tool path is the current one. `/v1/chat/completions` exists on regional endpoints too, but `/v1/files` is global-only, so the runner defaults to `https://api.mistral.ai/v1` and auto-falls back there on a route-miss 404. Prompts are static scene descriptions, so no learner personal data crosses; Mistral remains the processor under its DPA. | **Chosen** — license-clean, style-capable, current API |
| BFL direct (`api.bfl.ai/v1/flux-1.1-pro-ultra`) | $0.06/image Ultra, $0.04/image pro; separate account/key, US processing — weaker GDPR story for EU learners' context. | Fallback if the Mistral tool fails QC |
| **Illustrative style via the same Mistral tool** (`--styles=illustration`) | Same license/cost, no xAI; flat editorial illustration with azulejo-tile motifs matches the app's brand mark, but changes the product look (photos were a deliberate choice). | QC comparison arm — style picked in the QC gate |
| Hand-authored SVG/CSS scenes | Original art, no AI credit, but changes the product look and is high effort across 20 scenes. | Rejected |

## Cost / latency estimate (recorded)

- **Cost**: 20 images × $0.10 = **≈ $2.00** via the Mistral tool on the global
  endpoint (regional endpoints don't host this API, so no +10% applies here);
  BFL direct fallback $0.80–1.20. QC subset of 3 images ≈ **$0.30**.
- **Latency**: FLUX1.1 Ultra ≈ 5–10 s/image end to end through the
  conversations API; 20 images sequential ≈ 2–3 min, at concurrency 3 under
  ~1 min. Measured per-scene latency lands in `regen-log.json` when the script
  runs.
- **Prototype** (ready to run, not shipped):
  `MISTRAL_API_KEY=… node scripts/scene-regen/regen-scenes.mjs [--only=tram,cafe,street] [--styles=photo,illustration]`
  — prompt table in `scripts/scene-regen/prompts.mjs` (one prompt per scene,
  derived from `src/lib/scene-image.ts` settings + a locked shared style
  prefix per style: `photo` = current photoreal look, `illustration` = flat
  azulejo-branded editorial illustration), runner downloads the image,
  post-processes to 1200 px progressive JPEG q82 via sharp, and writes
  `scene-regen-out/` with `current/`, `styles/<style>/`, `qc.html`
  (side-by-side harness at the app's real crops — current + one column per
  style, per-scene pass/fail per style) and `regen-log.json` (latency +
  cost). `--dry-run` prints the prompts without spending quota. The runner
  calls `POST /v1/chat/completions`
  with `tools:[{type:"image_generation"}]`, extracts the image URL from the
  `role:"tool"` message's JSON-string content (Azure blob URL; `image_url`
  chunks and `tool_file`/`file_id` as fallback) and downloads it. Model fallback chain `mistral-small-latest → mistral-medium-latest →
  mistral-large-latest` (override via comma-separated `MISTRAL_IMAGE_MODEL`);
  a model whose response carries no image reference falls through to the
  next. Default base is the global endpoint; on a "no Route matched" 404 from
  a regional base it falls back to `https://api.mistral.ai/v1` automatically
  and records it in the log.

## Visual QC gate (acceptance criterion 1 — executed 2026-11-15)

Run by the owner with `MISTRAL_API_KEY=… node scripts/scene-regen/regen-scenes.mjs
--styles=photo,illustration` (full 20 scenes, both styles) and reviewed in
`scene-regen-out/qc.html` against the pass criteria: style consistency within
the set; subject recognizable at the 16:9 center crop; no
watermark/logo/gibberish text; people only where the current scene has them;
file size ≈ 90–260 KB.

**Result (owner-submitted QC report, 2026-11-15):** the **illustration** arm
was marked **pass on all 20 scenes** (`balcony … tram`); the photo arm carried
no verdicts in the submitted report. Recorded style choice: **illustration**.
Per-scene latency/cost measurements are in the run's `regen-log.json`.

## Recommendation

**Replace** the 20 scene JPGs via Mistral's built-in `image_generation` tool in
`/v1/chat/completions` on the global endpoint (`https://api.mistral.ai/v1`).
The QC gate is passed and the recorded **style is `illustration`** (flat
azulejo-branded editorial illustration — passed 20/20 in the owner's QC
report; the photo arm was not voted in that run). If the photo look is
preferred after all, re-run the gate with `--styles=photo` — the tooling is
identical. When the replacement ships: swap the 20 files, and in the **same
change** update `THIRD-PARTY.md` (drop the 20 scene paths from the
"Created with Grok" image list, add an AI-generated-with-Mistral entry) and
`src/routes/about.tsx` (credits line) plus `scripts/about.test.mjs`
assertions — see ADR 0008 consequences. The implementation ticket is #102.

## Consequences (shipped)

The replacement shipped in the #102 change: `public/scenes/*.jpg` (20 files)
now hold the `illustration`-style Mistral output from
`scripts/scene-regen/regen-scenes.mjs --styles=illustration`
(`scene-regen-out/styles/illustration/`), and the same change updated
`THIRD-PARTY.md` (scenes moved out of the "Created with Grok" list into a
Mistral AI section; `og.jpg` and the icon/mark keep their Grok attribution),
`src/routes/about.tsx` credits, `scripts/about.test.mjs`, and the
`src/lib/scene-image.ts` comment. File names are unchanged, so
`src/lib/scene-image.ts` mapping, the precache list and the offline cache are
untouched. ADR 0008's attribution obligation for the scenes is discharged; it
still covers `public/og.jpg` and the icon/mark until the icon follow-up lands.
